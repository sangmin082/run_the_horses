## horse-run-game 분석

빌드: Vite SPA (바닐라 JS), 엔진은 Web Worker로 분리. 소스가 공개되어 있어
보드 상수를 직접 확인할 수 있었다.

### 기능

- 모드: 1인용(AI) / 2인용(로컬), 선공/후공 선택, 게임 재시작
- AI: ① 미니맥스(성능 슬라이더: 깊이 2~5) ② **"딥러닝" 모드 — ONNX Runtime Web +
  MCTS** (AlphaZero 스타일 신경망, 워커 번들 822KB)
- 단판 승부 (3판 2선승 없음), 무르기·퍼즐·사운드·튜토리얼 없음

### 보드 정의 (소스에서 추출)

- 초원: **중앙에서 맨해튼 거리 ≤ 2인 12칸 다이아몬드**
  (`d6, e5, e6, e7, f4, f5, f7, f8, g5, g6, g7, h6`)
- 초기 배치: **각 코너에 ㄱ자(브래킷) 형태로 5개씩**, 플레이어당 대각 방향 두 코너
  - 선공: 좌상(a1,a2,a3,b1,c1) + 우하(i11,j11,k11,k10,k9)
  - 후공: 우상(a9,a10,a11,b11,c11) + 좌하(i1,j1,k1,k2,k3)
- 이동 규칙(슬라이드/L자·사막 제한)과 승리 조건은 우리 구현과 동일

### 시사점 — 우리 가정과의 차이

우리 초기 구현은 초원 8칸(3×3 링) + 대각선 일렬 배치로 **가정**했으나, 팬게임은
12칸 다이아몬드 + 코너 브래킷 배치다. 팬게임은 원작 방영분을 보고 만든 것이므로
후자가 원작에 가까울 가능성이 높다 → **우리 엔진도 이 레이아웃으로 전환**
(`engine/src/board.js`). 위키의 "각 대각선 위치에서 마주보는 형태로 5개씩"도
"대각 방향으로 마주보는 두 코너에 5개씩"으로 읽으면 부합한다.
최종 확정은 원작 영상 대조로 한다 (TODO 유지).

## 기능 비교표

| 기능 | horse-run-game | **우리 (run_the_horses)** |
|------|----------------|---------------------------|
| 플랫폼 | 웹 | 웹 프로토타입 → Flutter 모바일 목표 |
| AI | 미니맥스(깊이 2~5) + MCTS/신경망 | 미니맥스+알파베타+TT+반복심화 (4단계) |
| 매치 형식 | 단판 | **3판 2선승 + 라운드별 선공 교대** (원작 재현) |
| 퍼즐/학습 모드 | 없음 | **12문제 (자동 생성)** |
| 무르기 | 없음 | **있음** |
| 사운드 | 없음 | **있음** |
| 온라인 대전 | 없음 | 로드맵 Phase 3 |
| 밸런스 보정 | 선공/후공 선택만 | **파이 룰 (데이터 검증됨)** + 밸런스 리포트 |
| 룰 엔진 테스트 | 미확인 | 단위 테스트 30개 + CI |

## 차별화 전략 (앱스토어 심사 4.3 대비 겸용)

1. **원작 형식 재현**: 3판 2선승 + 선공 교대는 우리만 구현
2. **학습 곡선 설계**: 퍼즐 모드 → 튜토리얼로 확장 (신규 유저 온보딩)
3. **검증된 밸런스**: 시뮬레이션 데이터에 기반한 파이 룰 랭크 모드
4. **온라인 대전**: 팬게임 생태계에 없는 기능 — 최대 차별화 요소
5. AI 강화 옵션: 팬게임의 신경망 AI가 체감상 더 강할 수 있음 → 장기적으로
   자가대전 학습(AlphaZero-lite) 검토 가치 있음
